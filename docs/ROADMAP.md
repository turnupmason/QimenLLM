# 阶段计划与验收

每阶段记录源码 commit、数据版本/快照哈希、实际命令、通过/失败/未评估、失败复现和下一步。不能以命名版本或报告代替交付。

| 阶段 | 交付与可运行程序 | 数据/测试门槛及失败处理 | 进入下一阶段 |
|---|---|---|---|
| 0 工程基础 | 新 Git/Python 项目、持久文档、v1 schema、import/annotate/audit、统一问事和学习入口、WSGI、双设备准备 | 空领域库；工程回归与实际命令通过，失败先修；不导旧数据或训练 | 等用户第一章，完成当前交付后停止 |
| 1 神奇之门基础 | 按章保全原文/来源、上下文标注、知识关联、受支持规则编译 | 版本化增量库；完整性和实际知识事实回归，疑点保原文、未编译单列 | 对某项算法有完整来源和可执行验收条件 |
| 2 起盘/用神 | 独立历法/排盘方法与专业条件绑定接入 service | 方法版本、来源盘逐项/边界/关系/缺条件测试；不通过不升级 engine_verified | 有完整案例资料与可靠盘面/规则支持；未完项明确 |
| 3 完整案例 | 事件、多盘、对话、作者依据、预测/反馈/续断、候选任务工具 | 逐案例资料版本；完整性、跨书同事件、时间隔离；未知历史不强迫补 | 足够独立完整事件与可评分任务支持基线，不预定案例数 |
| 4 专业基线 | 可替换模型适配、五级系统消融、冻结评估 runner | 事件家族 release 与公平配置，真实模型请求/格式/专业评分分开；不泄漏 | 有质量合格训练集、冻结测试与实测 GPU |
| 5 首轮 SFT/LoRA | 实测选择模型、独立 CUDA lock、训练/恢复/产物 manifests | 数据/模型 revision；显存/稳定性/恢复与盲测对照；无提升不宣告掌握 | 有可靠实验流程及用户下一本文献授权 |
| 6 多古籍 | 开悟之门与后续来源，跨书概念、分歧、独立方法 | 增量版本、迁移和专业回归，不默认混流派；资料不足标待确认 | 多模式服务达到专业与安全门槛 |
| 7 正式产品 | 自然多轮、Web九宫、课程案例练习、账户隐私、反馈、部署运维 | 真实前端/API/service/DB/model/校验全链新问题测试；安全、恢复、压测和权利审查；失败不发布 | 有明确运营授权与可测服务质量 |
| 8 持续研究运营 | 扩展书籍/案例、模型改进、成本/可靠性监测、独立现实反馈研究 | 版本对照、漂移、预登记现实预测及完整结果；定期备份恢复，回滚有依据 | 持续迭代，不预先宣称最终成功 |
