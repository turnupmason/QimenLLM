# 全章节独立案例测试最低标准（2026-10-18 用户补充，优先级高于下文历史实验说明）

范围是《神奇之门》已提供的全部15个预测专题（人体疾病、恋爱婚姻、怀孕分娩、求学考试、工作就业、经营求财、出行出国、行人走失、刑事案件、官司诉讼、体育竞赛、天时气象、地理环境、人生机遇、钱物丢失），加上基础规则、起盘、应用概述和附录的来源知识评估；绝不是3个Development章节。随后新增案例及新增问事专题必须进入同一动态章节覆盖审计。

每个预测专题至少要有一个**独立、从未参与训练的完整案例家族**进入最终封存test；训练期间还须有独立validation家族以选模型，development属于开发调试，不要求每章有development但不能代替test。一个完整case/事件家族可衍生多张盘、多轮续断、多道方法题，统计独立案例只计其家族一次；初断可知输入不能包含预测、事后反馈或目标答案，后验复盘和仅依据作者结论/条件的题不能冒充真正独立首断。若没有资格充分的案例，就明确标记coverage_blocked，绝不拿已训练题或重复古籍内容凑1例。每章测试的“有1例”只是最低样本量，不能由单例成功宣称预测表现可靠；需按逐章事实、用神、证据、应期、整体预测和后续问事分别评估，再由独立现实预测评价泛化。

**现有冻结v1不能改动或重分**：265 train、60 validation、9 development、57 test只是任务数。当前6个预测专题无test任务（人体疾病、怀孕分娩、求学考试、天时气象、地理环境、人生机遇），5个预测专题无validation家族（求学考试、工作就业、人生机遇、官司诉讼、出行出国）。其余专题虽有test任务，是否由合格完整、无辅助首断的独立家族组成，仍要在单独离线冻结审计中验证；对任何章节不得暂标pass。正在运行的旧版本全书缓存保持不变，57test继续封存，不能拿它调参。

新增案例：先按问事及来源审读确认章节键、同一真实事件的family_id、多盘及披露时序；以新release版本追加，不覆写旧数据。已有family_id沿用原split且跨章节/跨书重复必须识别隔离。对于真正新家族，先查所属章节的独立test缺口、再查validation缺口、再提议train归属；这只是离线冻结前的**分组建议**，仍须审查案例是否完整、初断输入是否事前且是否跨书重复，禁止因已见训练效果不佳而转移家族。没有登记的新专题进入来源审读/新章节注册队列，不猜章节名、不丢失新题；新登记后动态进入同一15+N专题验收。

程序入口：`scripts/book_chapter_audit.py`自动读取冻结manifest的全部章节，逐章报告有无test任务、未见validation家族和模型生成诊断；`training/chapter_case_coverage.py`从离线、逐案审读的**元数据**核对合格独立family计数并提供新家族分组建议/严格门槛。只有离线新版本的审读元数据完整时才能运行`python3 scripts/book_chapter_audit.py --manifest <新冻结manifest> --reviewed-case-families <逐案元数据.json> --require-minimum`。这两个模块均不打开封存test原文或答案，也不生成真实预测通过成绩。新案例从自由文本自动判定问事类别的端到端导入尚未完成，不能把已实现的章节键动态检查/分组建议冒充完全自动入库。

# 全章节方法微调：2026-10-18

用户要求扩大全部章节精编、持续微调和逐章验证，每次训练保存GitHub。固定三遍、仅钱物章的旧限定已撤回；旧失败试验、源文、旧gold、原94家族归属和旧冻结release不改。

## 本轮数据

`book_method_curriculum_v1`共391任务：265 train、60 validation、9 development、57 test。98故事均有逐源审读，26份章级来源均有教学任务。90新增故事330任务，加既有钱物8故事32任务、两种局部/重排来源读盘2任务、基础/附录资料阅读30任务。此处是方法子任务数，不是独立事件数或模型成绩。

跨章审读发现：行人走失例四与官司诉讼例四是同一起1996-11-23拐童案。旧家族分别归validation/train，因此新版隔离诉讼家族的全部3训练任务，保存quarantine，不修改旧DB、旧划分或将其移到别的集合。保留任务涉及97故事，另1故事仍有审读档案和隔离任务。全书独立事件数不能直接沿用94旧家族作无重复证明。来源证据与排除家族见`book_method_duplicate_isolation_v1`。

八个先完成的章节另有只作准备的stage-a冻结版216任务，训练132/验证34的前缀缓存正在处理。全书版通过相同基座和完整token序列内容键复用这些张量；旧stage-a文件不重写。

学习附录的理论段落与后面的三个引例分开；后段含已在validation的经营求财彩票案，禁止以另一份精校源为名塞入train。基础和后记/传记教学是来源阅读，不是历史首断。回顾已知结局、混合反馈段落和不完整盘分别标明；不凭记忆补原书没有的推理。

每条输入与目标保留原始字节选择器、来源哈希、盘/事件/家族和披露轮次；完整故事档案含结果，只作归档与评分，不作为训练输入。泛用规则引用是文献参考；给定作者条件不是正式规则编译或程序复算。未知空亡、马星和日期边界继续为未知。

## 新一轮配置与真实执行顺序

固定使用本地已有Qwen3.8-27B-4bit，revision `10c35caafbb80f7dc6a7a432cdd11af10a6d4818`。在24GiB M2上保留0–62层冻结前缀，最后63层的q/k/v/o及MLP gate/up/down共7模块做rank16、scale2、无dropout LoRA。仅最后层可训练，因此缓存可保持全序列精确等价；不能以后悄悄解冻前层而继续用缓存。

每轮最多30个epoch，验证NLL连续6遍无至少0.001改善才停止该候选；每5遍保存候选并比较真实生成。学习率5e-5、单样本batch、完整最长8192token，不截断或只缓存前N个词。输出上限1536token，基座和微调同设置。NLL只是选择候选，不是专业方法或真实预测准确率。

依次完成：当前缓存→全书325条train/validation精确缓存→同27B全validation/development与缺失章节的已见诊断基线→真实下一更新保存恢复等价→正式优化→五遍或提前停止边界→全模型重新载入适配器与逐张量核对→同题生成→逐条来源审读。测试57条保持封存。全部问答均由QimenService.ask显式本地BookMethodRequest进入，HTTP和正式问事门槛不改。

持续脚本序列化所有27B进程，避免同时加载两个大模型。每个阶段用独立日志、身份与状态回执保存；失败后由本线程续查，不能把异常当完成。每25更新与每遍保存不可变权重、优化器、随机状态、游标和文件哈希，允许精确恢复；不覆盖失败模型。后续轮次由错误诊断决定，而非无上限背诵同一验证答案。

## 通过标准

所有被评题目须完整生成、有可用引用、盘面事实无误；读盘题指定事实召回100%，角色保留适用条件，综合保留反证和未知，应期保留原有候选及口径，续断只用本轮已披露信息。JSON通过不等于上述专业通过，语义结果须逐源审读，不能由loss自动填为pass。
