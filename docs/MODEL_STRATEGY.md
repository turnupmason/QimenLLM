# 2026-10-18 最新产品架构决策：一套共享专业模型服务所有问事专题

此决策按用户原始Master总指令、professional_training_summary和当日明确澄清执行；优先于本文后方历史模型选择建议。最终QimenLLM面向普通用户是**同一聊天服务、同一正式QimenService.ask流程**，提供AI问事和古籍学习两个模式。用户无需知道自己属于哪一章，更不能要求用户在20个独立模型中自行选择。默认训练并部署**一个跨全书、跨专题共享Qwen3.8-27B+LoRA专业模型**，在可复现的独立评估和真实系统对照未过之前不称其已具备专业断案能力。

统一正式问事管线：自然语言及多轮历史 → 识别意图、问事子类、人物关系、时间/地点及确实缺少的必要条件 → 动态章节/专题元数据目录选择一个或多个相关专题（例如工作调动和薪资求财）→ 参数化来源检索、精确方法标识与条件适用性过滤（不能根据关键词就激活用神，不能把不同古籍或流派无条件拼接）→ 确定性起盘引擎生成单一不可变盘 → 条件通过后用神绑定、证据与来源准备 → 共享专业模型输出结构化分析 → 程序核对盘面及规则依据 → 通俗/专业解释和出处 → 多轮新增信息与反馈续断。所有模型分析必须经同一条生产入口，训练时的source-conditioned研究分支不能冒充正式产品推断。文献学习与AI问事共享资料和基础事实，但对历史答案/事后反馈具有严格不同的访问权限。

路由**识别专题不等于选择模型**：专题是知识索引、条件规则、案例组织与逐章评估维度；模型实例默认只有一个，允许同一问事同时检索多个相关专题并注明方法来源/分歧。多意图或子类不明确需结合上下文追问必要信息，不能靠表面关键词硬猜；模型和规则都缺少足够支持时应block，不能伪造起盘或专业结论。不能用年龄取代人物关系，不能把历史作者判断当现实独立验证。

未来新增章节/书籍：逐章按用户提供来源增量接收、准确分类、案例家族跨书去重、时间隔离、保存来源及版本；分类目录从数据库/版本化数据注册表读取，不把15个专题写死进问事路由。遇到新专题需要审读并登记，而非生成凭空存在的规则；新增知识先使共享模型通过受条件控制的检索可见，再积累新训练资料，追加版本化多专题SFT/LoRA并做之前未见的逐章独立评估。旧冻结train/validation/development/test及封存题不得重分或作为调参材料。每个预测专题至少一个真正完整、事前隔离的独立最终test案例家族，训练期间还需要未见validation案例支持模型选择；一案多题不计多例，单例正确不意味着某章现实预测可靠。

**仅在出现独立、可复现的专题验证证据时**，才允许考虑保留共同27B底座、增加可热切换的专题LoRA adapter。不得默认训练20个完整独立大模型或把一个章节绑死到某一权重；专题adapter必须回归跨专题/混合问题、统一入口、方法冲突、算盘正确性、冷启动/内存/延迟与校验表现。路由只可以选择已登记且验收通过的adapter版本，失效后必须退回同一共享专业模型或安全阻断。多Adapter是将来的可选优化，不是当前训练拆分。

**当前真实实现缺口**：`src/qimenllm/conversation/interpreter.py` 中`ExplicitContextInterpreter`仍只保留外部显式传入的domain，未从自然语言自动识别专题；`QimenService.ask`正式入口仍受独立起盘/用神条件/验证门槛约束而blocked。当前Qwen3.8-27B的Mac全书训练与逐章测评是受控研究阶段，未形成真正对普通用户开放的自动路由问事产品。本决策仅确定架构，不得把文档视为已实现自然语言路由、正式专业推理或全部专题通过。

# 模型与训练路线

最新修订：用户指定的目标仍为Qwen3.8-27B + LoRA/QLoRA，但已明确撤回固定50个epoch要求。Mac改为优先准备五类专业任务与评估，用户可在RTX4090执行训练；轮数和配置在合格数据、完整系统基线及实际硬件检测后依验证集决定。旧49作者原话复现/finalblock配置退役，0正式训练遍/0更新，不作为专业方案。15个27B文件已下载并核验，早期“未下载”是历史状态。详见PROFESSIONAL_TRAINING.md与现行机器计划，以下旧段落中冲突表述以本修订为准。

当前（本地研究更新）：用户要求先Mac尝试建模。M2/24GB已实测Metal可用，首轮采用Qwen3-4B-Instruct-2507的MLX社区4bit转换版本作可替换开发候选；已下载校验约2.28GB文件，无API推理、无训练作业。真实开发调用经QimenService.ask的显式本地research分支；默认正式问事仍Unconfigured/blocked，不能以研究输出冒充专业完成。完整条件规则和冻结盲测门槛未完成，细节见MODEL_BASELINE.md。本轮用户指定只本地，不推送公开GitHub。

## 选择前的门槛

1. 实测家庭 GPU 机器 OS、CPU、内存、磁盘、4090 显存/驱动及 CUDA/PyTorch 组合；Mac 环境另立。
2. 核对候选精确版本、权重获取途径和商业/微调/分发许可。Qwen 等仅为候选，不提前锁定模型。
3. 在同一事件冻结题集测原始模型，再测盘、检索、完整条件规则系统。强 API 可作为研究基线，但需隐私授权与成本预算。
4. 记录上下文、结构化协议遵循、显存峰值、tokens/s、首 token 延迟、截断/失败、长案例证据保全、专业任务评分；相同输入、版本及生成设置公平比较。

优先实测约 7B–9B，是否采用更大模型由测量决定；24GB 不等于任意上下文和优化器都可训练。Mac M2 24GB 可做轻量推理，不取代 4090 训练。

## 分层分工

确定性工具负责固定事实和盘；运行时数据库负责来源、条件与方法；模型负责理解、证据组织和专业解释。LoRA/QLoRA 学习问事、步骤、类象条件、证据取舍、专业判断、应期与续断，不要求权重背诵盘面。

根据实测兼容性建立独立 CUDA 环境，可评估 PyTorch / Transformers / PEFT / TRL / bitsandbytes；不在 Phase 0 安装巨型依赖。选择后锁定精确版本和模型 revision，保存 lock/环境导出、GPU 信息、随机种子及训练配置；无偏好数据不启用偏好优化或 RL。

## 数据与实验记录

完整事件家族隔离，训练候选需原文/规则/案例 ID、时刻可知输入、目标、证据、split、审核、版本/哈希。案例不能无声截断或靠重复扩增。人工确认的作者依据与模型猜测分开。

每次实验清单必须包含：experiment_id、Git commit、模型及 tokenizer revision/许可、数据 release/清单哈希、训练/验证家族、LoRA rank/alpha/dropout/target_modules、epoch、optimizer steps、学习率与优化器、batch、gradient accumulation、上下文长度、截断策略、随机种子、精度/量化、设备/软件版本、峰值显存、速度、loss、checkpoint/resume、独立测试结果和基线差异。

训练和推理 artifact 只存版本化 manifest 与外置权重引用，不无计划进入 Git。保留模型、适配器、tokenizer、优化器、scheduler、RNG 及数据游标，实际测试中断后恢复一致性。详细接入见 HARDWARE。

## 成功标准

同条件对照显示可复现专业提升，基础事实与条件错误不退化、格式错误单独改善，盲测完成率与正确性同时报告。loss 降低、20 步优化或流畅断语均不够。历史复现、作者叙述结果与独立现实预测三者不能互相代替。
