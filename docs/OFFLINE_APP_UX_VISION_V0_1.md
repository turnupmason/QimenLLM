# QimenLLM / 离线手机 App · 首版用户体验构想（V0.1，讨论稿）

状态：用户 2026-10-19 提出的产品体验构想；**仅作为可迭代 UX 草案，不代表已经实现，不构成改动现有 QimenLLM 训练、古籍数据库、冻结数据、起盘代码或既有产品需求的指令。**

## 产品方向
- 先把**时家转盘**这一流派单独完成并验证；以后按流派逐个扩展，不同时开发所有流派。
- 已有 QimenLLM 古籍数据库和基础知识是研发资产；仍需核验所需的完整规则、条件与准确起盘是否真正落实为可执行代码，不能将“数据库有知识”视为“已完成专业断案引擎”。
- 产品目标是以精致视觉和简易操作为核心的**离线手机 App**：起盘、取用、证据组合、模板式解读与展示本地运行。GPT 可在开发阶段协助制作和审校候选解词，但手机端不强制依赖在线大模型。
- 每个流派有独立的起盘定义、适用规则和测试；不同流派之间只能复用明确验证相同的知识，不预设所有流派断案规则一模一样。

## 用户原始操作流程（按用户提出的顺序保留）
1. **初次打开：云里雾里的动态开场。** 有简短、有氛围的 App 介绍，形式参考新安装 App 的首次上手引导，快速告诉用户如何使用。
2. **进入问事专题选择。** 例如健康、婚姻、工作、求财、寻物、出行、天气等，后续按验证完成的专业专题扩展。
3. **选择与该事情的关系。** 如“问我自己的事情”“替朋友问”“替父亲/母亲问”“父母替子女问”等。UI 需要在必要时区分“发问的人”和“事件主角”；不能把年龄、关系和用神混为一谈。
4. **起盘前 1 分钟静心仪式。** 画面提示：“起卦之前，请闭上双眼，静下心来，在心中专注于这件事。”用户希望保留“心诚则灵”的东方传统仪式氛围。**这是体验/文化表达，不作为科学验证过的预测效果承诺。** 自 60 秒倒计时开始，用户可以暂不操作手机。
5. **计时结束，自动依设备当前本地时间起盘。** 必须明确采用“60 秒结束的瞬间”为正式起盘时间，而不是进入静心页的时间；必须留存实际时间戳、设备时区、所选流派和规则版本（涉及节气/时辰边界时尤其重要），以便计算复现和纠错；不能伪装成所有时刻盘都相同。
6. **展示九宫盘以及已验证的专业解读。** 将盘面事实 + 所选问事专题 + 人物关系 + 古籍适用规则 + 必要补充条件组合，调用**预写且经过审读的解读片段**；不要依赖“每个盘×每个领域固定一条通用断语”，否则同盘不同关系/事情会被误判。
7. **下方展示断案方法与证据逻辑。** 可依次展开：取用神依据 → 宫位/门星神/干等实际盘面证据 → 生克旺衰、格局、反证与冲突 → 适用的应期方法 → 原书依据及局限。没有足够条件时必须提示缺失，不能硬写结论。
8. **最后用一句醒目的加粗总结。** 在不保证现实预测应验的前提下，以自然、清楚的语言归纳“按该传统方法得到的倾向判断及限制”；不把历史术数解读包装为医学诊断、投资指令或事实预言。

## 首版体验细节（待进一步商量，而非已定）
- 首次引导与每次起卦的静心仪式区分：新手引导适合首开出现、此后可以快速进入；静心 60 秒按用户原始设想每次起卦执行。
- 动态风格：雾、云、墨、微光，短促而有质感，界面文字清晰，避免长期遮挡可读内容。日后可考虑减少动态效果、离线资源包和无障碍。
- 专题类别应来自实际规则注册表，不能出现尚未验证却可以点开的“专业全覆盖”。
- 关系选择需能覆盖本人、朋友、父母、子女以及复杂代问/多当事人的基本路径；初版先明确最常见的选项，稀有情况通过“其他”或补充步骤处理。
- 自动起盘前后遇到本地时间切换、节气边界、时区设置改变时，应保持方法透明和起盘结果可复现。
- 报告可提供简单/详细两层：一眼看懂的结论在显著位置；需要学习的用户展开宫位与古籍证据。
- 若用户选择改变当事人、专题或时刻，需明确是否重新起盘或仅重新分析已有盘，不应无提示篡改原盘。

## 验收门槛
- 正式离线断案能力尚未构建完成。不能将现有原书知识、27B LoRA 训练数据或模型输出直接标记为审定解词。
- 先验证时家转盘准确性、适用用神和专业规则优先顺序；按古籍案例核对取用条件、时间信息、证据组合与推论限度。严守历史案例事前隔离和原本封存 Test，不把已看作者结论的实例伪称独立盲测。
- 内容候选可以借助 GPT 起草与资料比对，但导入离线数据库需逐条审核来源和适用条件，不能混入未证实的另一流派解法。
- 手机数据默认设备本地处理，避免上传用户问事详情；隐私、网络依赖及模型调用承诺必须与真实实现一致。

## 项目协作边界
此文件仅保留 2026-10-19 的产品方向，方便后续逐屏、逐细节迭代。现有 Github 冻结数据、27B 模型检查点、本地工作目录、古籍知识库存档和生产问事实现全部保留；不擅自删除或重构。待确认新路线的工程阶段目标之后再另起明确版本的离线 App 实验分支/模块。
