## 原文与版本

完整输入按 UTF-8 bytes 保存到 SQLite BLOB 和 SHA-256 内容寻址镜像，不去 BOM、不规范空格、不转换 CRLF、不重排图表。哈希代表本次收到的字节，不能证明与用户未上传的纸本或剪贴板逐字相同。扫描图等二进制附件将新增有哈希的媒体来源接口，当前 CLI 只接收 UTF-8 文本；图盘不能靠猜测补字。

`book_key` 包含版次标识，`chapter_key` 标识整章/完整知识点；原文顺序单独保留。相同书章、相同字节幂等；不同字节必须显式下一 revision；原版本永存。书/章元数据冲突明确报错。另一次同文用户确认追加 review，不改正文。

来源片段使用 UTF-8 字节边界、revision 和 locator。段落、页码或图坐标只能来自实际材料。整体先保存再标注，引用片段不能取代完整上下文。原文、来源、数据版本及编译规则为 append-only。阅读整理副本将另存，不能改 authoritative content。

## 分层与状态

基础属性、起盘、类象、角色、断案、应期、注释分别保存；概念支持跨书链接，规则绑定方法版本。`knowledge_items` 独立记录 structured、applicability_confirmed、compiled、reference_only、disputed、training_allowed、evaluation_only；原文确认由 source_reviews 表示，编译和复算不是其替代。

标注工具支持整块上下文 + payload + 来源片段，默认仅结构化/参考，不能自动升级可执行规则。没有受支持的算法、准确条件和测试，不设置 compiled。未编译知识仍是有效资料，不强迫用户补历史中不存在的信息。

知识编译必须核对适用领域/子类、起局口径、问/被问身份、六亲关系、前置与排除条件、组合用神、例外、多方法及争议，记录条文与版本。不将类象当固定属性，不把作者案例经验推广成通用法则。

## 每次输入工作流

1. 收到完整章或完整知识点；多段时待用户说明完整范围，保留输入顺序。
2. 保存原文、书章标识、来源与哈希，审计重复与版本。
3. 精读上下文，整块标注，关联概念、方法、规则和分歧；技术适用条件缺失时标待结构化或待技术覆盖，不重新要求用户确认原文，不编造。
4. 对实际足够且可确定的知识编译，加入有来源回归测试。资料确认与程序验算分别记录。
5. 运行完整性与相关专业测试，更新数据版本、知识覆盖、STATUS 与接收记录，准备下一部分。

文献不够时不生成表面完整的知识库。没有模型、检索和规则的实际端到端证据，不宣称模型已学会。

版权状态默认 unreviewed；research_authorized 与 public_authorized 分离。研究 API 在本地读取用户资料，不提供公众全文服务。公开或商用训练需按具体书版本与权利单独核实。

用户后续已明确要求 GitHub 持续更新。每次资料更新的真实原文字节及结构化权威表经 snapshot 进入指定私有仓库，保留来源和哈希；本地 SQLite/镜像不直接提交。上传失败明确 pending，不能只保存本地就结束。详见 GITHUB_SYNC；该备份授权不扩展为公众分发或个人问事训练授权。
