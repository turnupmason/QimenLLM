## 使命与合作责任

建立面向全球普通用户的专业奇门遁甲垂直 AI 平台，把专业知识系统、独立确定性起盘、完整历史案例学习与可替换语言模型结合。普通用户像使用 ChatGPT 或 Claude 一样自然提问，学习者可以研究古籍和作者完整断案方法。不是仅排盘、搜索或套固定断语模板。

Codex 承担 AI 架构、模型研究、文献知识工程、规则系统、全栈开发、测试及持续维护工作。在授权环境实际编写、运行、验证并形成可复现交付。不能把计划当完成、代码当集成、数据库当模型已掌握、表达流畅当断案正确。

最终能力包括：自然中文对话；多古籍理解与检索；独立起盘；有条件的用神选择；古籍方法适用性判断；宫位、门星神、天干、生克、旺衰、格局证据综合；作者方法迁移；应期和复杂分歧；反馈续断；专业教学；严格事实验证；公开产品运行与改进。模型学习作者运用知识的方法，而不是机械背诵历史结果。

## 两种产品模式

**AI 问事**：考试、工作、失物、健康、感情、出行、合作经营等自然语言问题。系统识别具体背景，只询问缺失且影响方法的最少必要条件。已知时间地点人物关系不重复问；普通用户不自行选择用神。合法多方法应说明或请用户选择，不能暗中认定唯一方法。

执行顺序：理解问题 → 条件确认 → 起盘 → 动态检索 → 规则适用判断 → 用神绑定 → 盘面和规则证据 → 专业模型分析 → 校验 → 通俗回答 → 多轮反馈。条件不足时真实报告，不能空答计成功。

**古籍学习**：从基础到高阶，按书章、术语和专题学习；九宫八卦、门星神、干支五行、起局排盘、用神、类象、旺衰、格局、应期；完整案例与作者步骤；用户先分析再对照；分级练习；引导思考时不直接泄露答案。严格区分原文、作者具体判断、系统讲解和模型分析。

**体验**：初期中文，预留英文；简单问题简洁，复杂问题可展开证据；高级用户可看九宫、用神、来源、规则分歧和可审查分析。用户无需懂术语也能使用，并能逐步深入学习。

## 硬件与模型

家庭 RTX 4090 24GB 是主要本地模型实验与训练资源。OS、CPU、RAM、磁盘、CUDA及可连接性尚未确认，首次使用前必须实测。Windows 可评估 WSL2，Linux 则使用兼容 CUDA 工具链。MacBook Air M2 24GB 是开发、文献输入、审查、轻量测试、小模型和远程控制设备。两机共享 Git 与版本化数据，环境隔离，支持日志、断点恢复与加密鉴权。开发机、训练机、推理服务和公众服务器分开；未来可迁移云 GPU，不提前采购或暴露公网。

不从约 20 本书从零预训练通用大模型。候选开放权重中文模型（含适用的 Qwen）及强 API 基线，许可必须允许预期用途；模型可替换。优先实测约 7B–9B，是否更大由上下文、量化、显存、稳定性决定。考虑 PyTorch、Transformers、PEFT、TRL、bitsandbytes 等实际兼容生态，不承诺未测能力。

LoRA/QLoRA 应学习复杂问题理解、分析组织、多证据取舍、类象解释、作者判断模式、应期、反馈续断和自然中文表达。确定性固定事实由程序提供。必须与未微调系统公平比较，loss 下降或少量优化步骤不等于掌握领域；没有高质量偏好数据，不贸然进行偏好优化或强化学习。

## 分层知识与检索

保存九类：不可变原始文献；固定基础属性；历法及排盘规则；上下文类象；用神条件；宫内跨宫等断案方法；应期；完整历史案例；跨书概念、流派约定与分歧。规则均须来自实际输入，不默认跨书任意组合。

知识状态独立表达：原文确认、结构化、条件待确认、确定性编译、传统参考、争议、训练许可、仅评估。原文确认不是已执行，未编译不是资料无效。

检索顺序：理解具体问题与人物关系 → 参数化候选查询 → 条件检验 → 方法隔离 → 用神绑定 → 来源与依据返回。可组合 SQLite、全文、语义、术语与排序，语义相似不能替代条件决策。兄长不能因为年龄较大被自动当作父母长辈。

状态为 applicable、conditional、excluded、disputed、reference_only。未知不作真，只有 applicable 可自动绑定。每次保留问事结构、查询、候选、激活与拒绝理由、来源和角色，集成测试证明运行时真实访问数据库。

## 排盘与数据对象

仅在收到算法后逐步实现：时间标准、地点、历法节气、四柱、阴阳遁与局数、置闰拆补等起局、旬首、值符值使、九宫、天地盘、星门神、干落宫、空亡马星和书中可确定格局关系。方法参数和版本明确，不能混算法。处理时区、交节、换日及历史时间不确定性；缺条件明确无法确定的部分。

盘对象不可随意改写，至少考虑 chart_id、原始时间、timezone、location、casting_method、method_version、four_pillars、bureau、palaces、heaven_plate、earth_plate、doors、stars、deities、voids、horse、derived_facts、source_or_engine、validation_status。字段随真实算法演化；不存在的历史信息用未知而非编造。UI、推理与校验消费同一张盘。

## 完整案例与时间隔离

关系链 Book → Case → Event → Chart → DialogueTurn → AnalysisStep → Evidence → Prediction → Feedback，允许多事件、多盘和跨书同事件。保存背景、人物关系、时间方法、原书盘、对话、作者用神、宫位事实、宫内跨宫关系、生克旺衰格局类象、证据取舍、断语、应期、反馈、续断与结局。每步关联原文段落、盘、规则、用神和宫位。

明确作者判断前已知、判断时依据、事前预测、后来反馈和续断；反馈不得提前进入输入。作者没写的推理不得虚构，简明可验证证据步骤可训练，内部心理过程不可伪造。案例特殊方法不得未经验证推广成通用规则。

## 训练数据与评估

基础任务可含属性、术语、条件适用、用神、纠错、信息不足和方法比较。案例任务可含角色选择、盘面关系、作者证据组合、类象理由、方法比较、基于当时信息分析和反馈后续断。

每样本有任务类型、来源和 ID、预测时可知输入、目标、证据、数据划分、验证状态、版本与哈希。不得编造、重复扩增；长案例不能无声截断，必须有完整可审计的处理方案与证据保全检查。

按事件家族划分 train/validation/test，跨书重复、多盘、多轮与同源任务同组；独立新日期新盘新问题另设 unseen。训练前基线比较：基础模型；加确定性盘；加正确检索；加完整条件规则；以上系统再 SFT/LoRA/QLoRA。相同题与生成约定，权限隔离、事件冻结和可复现随机种子。

每次记录模型版本、许可、数据/分组、LoRA 配置、epoch、steps、学习率、batch、梯度累积、上下文与截断、显存、loss、检查点、测试与基线差异。不凭 loss、版本号或报告宣告进步。

六层验收：资料完整性；基础事实；排盘；用神选择；综合断案；独立新问题与真实产品。已覆盖的确定性事实必须全通过；未实现层不得标通过。分别统计条件识别、生成协议失败、断案完成与专业正确性；空答案和阻断不能充成功。现实预测需预先登记判断与后续结果，历史作者复现不等于现实预测准确率。

## 输出与正式链路

原则性错误零容忍：生克方向、固定属性、落宫、天地盘、本宫与落宫、同宫与跨宫、无条件角色绑定、方法混用、反馈泄漏、伪造来源以及内部矛盾。

模型先输出结构化、可引用盘面事实或可用规则的分析，程序检查证据与条件，验证后解释层生成文字，并再次检查可验证事实。JSON 不全、截断、生成中断、缺引用、原盘不可解析分别记录，不全归为知识错误，也不全归为阻断成功。采用模型适合的结构化协议，不靠无限 token 或脆弱正则补洞。

正式问事只有一个统一服务入口，测试、API 和 Web 必须同路。开发追踪理解、起盘、查询、规则条件、绑定、模型请求与结构输出、验证、最终答复；调试记录需隐私控制。禁止新模块只在测试出现、网页或评估仍走旧 Prompt，禁止只在训练时用数据库，禁止终端答案绕过校验。
